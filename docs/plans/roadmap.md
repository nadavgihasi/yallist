**Later:** iOS build + Sign in with Apple (required once iOS ships) + Universal Links for invites, help choosing a place (teased in settings), more templates, more languages (the profile's language row stays disabled until then).

**Deferred: payment phone from Google.** The Google ID token carries no phone number. The People API (`people/me?personFields=phoneNumbers`) needs an access token with `https://www.googleapis.com/auth/user.phonenumbers.read`, a [sensitive scope](https://developers.google.com/identity/protocols/oauth2/scopes) ("See and download your personal phone numbers"). Unverified, every user who grants it sees the "unverified app" screen and the [100-user cap](https://support.google.com/cloud/answer/13464323) applies; removing both needs [sensitive-scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification) (privacy policy on the app's domain, scope justification, an unlisted YouTube demo of the consent flow). It also reads the user's Google profile phones, and nothing documents the sign-in or recovery phone being among them; developers report empty results even with the scope granted, so many users would get nothing. Until then the phone field's `autoComplete="tel"` lets the browser, Android autofill or the iOS keyboard fill it in one tap. If it's worth doing after D5 and the domain: (1) enable the People API in the yallist Google Cloud project; (2) add the scope under Google Auth Platform → Data access; (3) submit for verification; then (4) add a "הבאה מ-Google" button on `/profile` that asks for the scope with the GIS token client (`initTokenClient` + `requestAccessToken`, incremental, on tap), reads `people/me` in the browser, and only prefills the field for the user to confirm.
