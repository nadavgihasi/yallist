# Android builds

Builds run in GitHub Actions ([android.yml](../.github/workflows/android.yml)); nothing Android-related needs to be installed locally. `android/` is generated by `expo prebuild` in CI and never committed.

## Upload key

```sh
./scripts/create-android-upload-key.sh
```

Creates a PKCS12 upload key, stores it and its generated password as the GitHub secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` and `ANDROID_KEY_ALIAS`, and keeps a copy in `~/.yallist-keys/`. Back that folder up to a password manager. Release signing is wired in by [plugins/withReleaseSigning.js](../apps/mobile/plugins/withReleaseSigning.js); without the secrets, release builds fall back to debug signing (fine for sideloading, rejected by Play).

## Build

Actions → **Android build** → **Run workflow**. The run's artifact contains:

- `app-release.aab`: upload to Play Console → Testing → Internal testing.
- `app-release.apk`: install directly on a phone (allow "install unknown apps").

`versionCode` is the workflow run number, so every run can be uploaded to Play. Bump `version` in `apps/mobile/app.json` for user-visible versions.

## Play Console setup (after Google verifies the account)

- [ ] Create the upload key: `./scripts/create-android-upload-key.sh`, then back up `~/.yallist-keys/`.
- [ ] Run **Android build** and confirm the log no longer says "debug signing".
- [ ] Create app: name Yallist, default language Hebrew (he-IL), App, Free.
- [ ] Package name `app.yallist` (permanent; set by the first upload).
- [ ] Testing → Internal testing → create release, upload `app-release.aab`, accept Play App Signing (our key stays the upload key only).
- [ ] Add testers (email list), open the opt-in link on the phone, install from Play.
- [ ] App content: privacy policy URL, data safety form, content rating questionnaire, target audience, ads declaration.
- [ ] Store listing: short/full description, 512×512 icon, 1024×500 feature graphic, 2+ phone screenshots.
- [ ] Closed testing with 12+ testers for 14 consecutive days (required for personal accounts before production).
- [ ] Apply for production access.
